# 中午部署：一頁講完

> 版本 **v0.19.0**　｜　2026-07-29

---

## 先說這次部署的是什麼

**AI 題庫建置系統**，完整的一條動線：

```
上傳題本（PDF／掃描／手機拍）
   → AI 讀整頁、抽出題目與答案
   → 老師在校對介面逐題確認
   → 寫進題庫
```

加上讓它跑得起來的周邊：班級與名冊（CSV 匯入，讀得懂 Excel 存的 Big5）、
知識點圖譜、學年度、帳號與家長同意、以及資料庫層的租戶隔離。

**學生端還沒有。** 作答、評分、解析、智慧老師、能力分析要等後續批次——
schema 裡連考卷、任務、作答、成績這四組模型都還不存在，那是藍圖裡的
13 人週。今天部署的是你訪談時說的第一痛點（題庫建置太慢）的解法。

---

## 部署步驟

```bash
git clone <你的 repo> yunzhi && cd yunzhi
git checkout v0.19.0

cp .env.example .env
chmod 600 .env          # 裡面有資料庫密碼與備份金鑰
$EDITOR .env            # 見下一節

./deploy/scripts/docker-install.sh
```

安裝腳本會依序做：建立設定 → 安裝前檢查 → 建置映像 → 起相依服務 →
跑遷移 → 起應用 → 驗收。

---

## .env 一定要改的六項

| 變數 | 說明 |
|---|---|
| `APP_DOMAIN` | 對外網域。**少了它 web 會在第一次上傳題本時整個掛掉**，而且容器看起來是健康的 |
| `APP_URL` | 完整網址，含 https:// |
| `AUTH_SECRET` | `openssl rand -base64 48` |
| `POSTGRES_PASSWORD` | 同上產生 |
| `BACKUP_ENCRYPTION_KEY` | 同上產生。**弄丟就還原不了備份** |
| `AI_*` | 見下一節 |

其餘用 `deploy/scripts/gen-secrets.sh` 產生即可。

## AI 端點的設定

```bash
AI_PROVIDER=openai
AI_BASE_URL=https://你的閘道網域/v1     # 結尾的 /v1 不能省
AI_API_KEY=<你的金鑰>
AI_MODEL_HIGH=gpt-5.6-sol
AI_MODEL_MID=gpt-5.6-sol
AI_MODEL_LIGHT=gpt-5.6-sol
AI_MONTHLY_TOKEN_BUDGET=0               # 0 = 不限。先觀察一個月再訂
```

**部署完成後第一件事，跑預檢**（三十秒、幾乎不花錢）：

```bash
docker compose exec ai python3 /app/../tools/ai-preflight.py
# 或在 repo 根目錄，設好上面那些環境變數之後：
python3 tools/ai-preflight.py
```

它問四個問題，其中**「看得懂圖嗎」決定整個匯入模組成不成立**——
這條管線是「模型讀整頁影像」設計的。過了再跑
`python3 tools/verify-ai.py --pages 6` 拿真實講義量準確率。

第三方相容閘道對參數的要求互相矛盾（新一代模型只吃
`max_completion_tokens`、推理模型拒絕自訂 `temperature`），
系統會自動協商，你不必知道你的閘道屬於哪一種。

## 第一次登入之後的順序

系統首頁會依「擋住後面所有事的排最前面」列出待辦。照著做就對了：

1. **建立學年度**（`/settings/years`）——班級要掛在它底下，沒有它建不了班
2. **開班、匯入名冊**（`/classes`）——CSV 直接丟，Excel 存的 Big5 讀得懂
3. **登錄家長同意**——名冊建出來的帳號是停用的（個資法第 15 條），
   在名冊頁逐一按「登錄同意」才會啟用
4. **建知識點**（`/knowledge`）——**這一步不做，匯入的自動標註等於沒有作用**。
   建議先只做數學 A，每科約 4 到 8 小時的老師工時
5. **匯入第一份題本**（`/import/new`）

## 已知的限制（不是 bug，是還沒做）

**題目入庫之後是「待審」不是「已發布」。** 校對確認的是「抽取正確」，
不是「可以拿去考學生」。題庫頁看得到它們，但**發布的介面還沒做**——
目前沒有把題目改成 PUBLISHED 的路徑。這不影響今天，因為還沒有學生端
可以拿它們考試。

**沒有學生端。** 學生帳號建得起來、登得進去，但登進去只會看到
「學生端還在開發中」。

**離線安裝那條路是空的。** `docs/INSTALL.md` 提到
`docker-install.sh --offline`，但腳本不認得那個參數，而
`build-offline-bundle.sh` 不存在。今天的機器有網路就沒問題。

**建置機器需要能連 Docker Hub 與 binaries.prisma.sh。** Prisma 的查詢
引擎是執行期的硬相依，建置時會下載並烤進映像。若機房完全封閉，
要先在有網路的機器上 `docker save` 再搬進去。

## 出事的時候

```bash
docker compose ps                       # 誰沒起來
docker compose logs -f web --tail=100   # 應用日誌
curl localhost:3000/api/readyz          # 依賴檢查（第一次可能 503，等 40 秒）
curl localhost:3000/api/version         # 現在跑的是哪一版

./deploy/scripts/doctor.sh              # 一次跑完所有健檢
./deploy/scripts/rollback.sh            # 回到上一版（含資料庫）
```

**回滾之前先看 `/api/version`**，確認你要回的版本號。升級腳本用
`VERSION` 檔當映像標籤，版本對不上的話會回到錯的地方。
