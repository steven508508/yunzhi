# 部署：一頁講完

> 版本 **v0.29.0**　｜　2026-07-29

---

## 這次部署的是什麼

**完整的一條動線，從一份紙本題本到學生的成績單：**

```
上傳題本（PDF／掃描／手機拍）
   → AI 讀整頁、抽出題目與答案
   → 老師在校對介面逐題確認（數學式與化學式現在排得出來）
   → 寫進題庫
   → 挑題組卷
   → 派給班級或指定學生
   → 學生線上作答（隨機題序、伺服器計時、斷線不掉答案）
   → 交卷自動計分
   → 老師看全班成績與各題答對率
   → 學生看自己的分數、逐題檢討與解析
```

加上讓它跑得起來的周邊：班級與名冊（CSV 匯入，讀得懂 Excel 存的 Big5）、
知識點圖譜、學年度、帳號／家長同意／密碼重設、以及資料庫層的租戶隔離。

**v0.20.0 上線了學生端**（在那之前學生登入只看到「學生端還在開發中」），
**v0.21.0 補上三個「裝起來就是死路」的缺口**（科目、教職員帳號、授課指派），
**v0.22.0 是六份真實使用情境模擬之後的整修**——扮演裝機的主任、建題庫的
老師、出卷的老師、應考的學生、考試當天處理狀況的人、以及開學三個月後的
維護者，各自從頭走一遍，找出 113 個卡點、34 個阻斷，逐一修掉。
報告留在 `docs/情境-*.md`。

**v0.23.0 補上五塊原本標著「未做」的功能**：題目裡的圖、智慧老師、
能力分析、考試行為偵測、家長端，以及升學輔導的第一階段。見下一節。

## 部署步驟

```bash
git clone <你的 repo> yunzhi && cd yunzhi
# 不要 checkout 到某個舊標籤。clone 拿到的預設分支就是最新版，
# 而舊版少的往往不是「一個功能」而是整條動線：v0.20.0 沒有科目、
# 沒有教職員帳號、沒有授課指派，裝出來是一個開箱即用不了的空殼。
cat VERSION                 # 確認版本，應該是 0.27.0 或更新

cp .env.example .env
chmod 600 .env          # 裡面有資料庫密碼與備份金鑰
$EDITOR .env            # 見下一節

./deploy/scripts/docker-install.sh
```

安裝腳本會依序做：建立設定 → 安裝前檢查 → 建置映像 → 起相依服務 →
跑遷移 → 起應用 → 驗收。

Ubuntu 從零開始（沒裝 Docker、要設開機自動啟動）走
`sudo ./deploy/scripts/ubuntu-install.sh`，手冊是 `docs/UBUNTU.md`。
它處理 Docker 安裝、docker 群組、cgroup 記憶體控制器、時區與語系、
ufw（**Docker 會繞過 ufw**）、開機自動啟動。

## .env 一定要改的六項

| 變數 | 說明 |
|---|---|
| `APP_DOMAIN` | 對外網域。**少了它 web 會在第一次上傳題本時整個掛掉**，而且容器看起來是健康的 |
| `APP_URL` | 完整網址，含 https:// |
| `AUTH_SECRET` | `openssl rand -base64 48` |
| `POSTGRES_PASSWORD` | 同上產生 |
| `BACKUP_ENCRYPTION_KEY` | 同上產生。**弄丟就還原不了備份** |
| `AI_*` | 見下一節 |

其餘用 `deploy/scripts/gen-secrets.sh` 產生即可。

## AI 端點的設定

```bash
AI_PROVIDER=openai
AI_BASE_URL=https://你的閘道網域/v1     # 結尾的 /v1 不能省
AI_API_KEY=<你的金鑰>
AI_MODEL_HIGH=gpt-5.6-sol
AI_MODEL_MID=gpt-5.6-sol
AI_MODEL_LIGHT=gpt-5.6-sol
AI_MONTHLY_TOKEN_BUDGET=0               # 0 = 不限。先觀察一個月再訂
```

**部署完成後第一件事，跑預檢**（三十秒、幾乎不花錢）：

```bash
docker compose exec ai python3 /app/ai-preflight.py
```

它在 AI 容器裡跑，而且**只有這一條路**。宿主機上直接
`python3 tools/ai-preflight.py` 會是 `ModuleNotFoundError: No module
named 'httpx'` —— 宿主機沒有裝 Python 的那一套相依，也不需要裝
（`docs/UBUNTU.md` 的「這台機器上不要裝 Python 環境」）。
容器裡的環境變數就是 `.env` 那一份，不必再 export 一次。

它問四個問題，其中**「看得懂圖嗎」決定整個匯入模組成不成立**——
這條管線是「模型讀整頁影像」設計的。

過了之後，拿一份真實講義量準確率（同樣在容器裡，PDF 要先送進去）：

```bash
docker compose cp 你的講義.pdf ai:/tmp/sample.pdf
docker compose exec ai python3 /app/verify-ai.py /tmp/sample.pdf \
  --pages 6 --out /tmp/report.md
docker compose cp ai:/tmp/report.md ./ai-verification-report.md
```

第三方相容閘道對參數的要求互相矛盾（新一代模型只吃
`max_completion_tokens`、推理模型拒絕自訂 `temperature`），
系統會自動協商，你不必知道你的閘道屬於哪一種。

## 第一次登入之後的順序

系統首頁會依「擋住後面所有事的排最前面」列出待辦。照著做就對了：

1. **建立學年度**（`/settings/years`）——班級要掛在它底下，沒有它建不了班
2. **開班、匯入名冊**（`/classes`）——CSV 直接丟，Excel 存的 Big5 讀得懂
3. **登錄家長同意**——名冊建出來的帳號是停用的（個資法第 15 條），
   在名冊頁逐一按「登錄同意」才會啟用
4. **建知識點**（`/knowledge`）——**這一步不做，匯入的自動標註等於沒有作用**。
   建議先只做數學 A，每科約 4 到 8 小時的老師工時
5. **匯入第一份題本**（`/import/new`）
6. **組一份卷子**（`/papers`）→ **派出去**（`/assignments`）→
   學生在 `/take` 作答 → 老師在 `/grades` 看結果

## 上線第一天會遇到的三件事

**一、名冊匯入建議分班做，不要一次丟 200 人。**
每一個新帳號都要算一次密碼雜湊（bcrypt 12 輪，約 0.35 秒），
200 人大約要等一分鐘，畫面會停著。一班 30 人約 10 秒。
試算畫面在超過 40 人時會先告訴你大概要等多久，那段時間**不要重新
整理也不要重複按**（重按不會建出重複帳號，但你會以為失敗了）。

**二、家長同意可以整批做，也可以寫在名冊 CSV 裡。**
名冊匯進來的帳號預設是停用的（個資法第 15 條），要登錄家長同意才啟用。
CSV 多一欄「家長同意」（填「紙本」「現場」「線上」或「是」）就在匯入時
一起完成；已經匯進來的可以在名冊頁勾選批次登錄。**不要一位一位按**——
200 位大約是半小時。

**三、忘記密碼在名冊頁重設。**
沒有寄信功能（這些學生多半沒登記 email，機房也連不出去）。
實際流程就是學生跟老師講、老師在名冊上按「重設密碼」，畫面會顯示
一組新密碼——**那串字只出現一次，關掉就沒有了**，請當場抄給學生。
學生登入後可以在 `/settings/password` 自己改。

**四、派卷之前確認授課老師名單。**
老師只派得了「自己教的科目 × 自己教的班」。這個檢查看的是
`class_subject_teachers` 那張表。如果某位老師實際教三個班而資料只
建了一列，他派另外兩班時會被擋下來（錯誤訊息會指名是哪個班）。
**開學前抽查一下那張表**，比當天現場處理省事。

## v0.23.0 新增的五塊

**題目裡的圖。** 管線一直找得到圖，但沒有任何地方把 `![[a:fig1]]`
換成圖片——一道「如右圖」的幾何題，學生看到的是題幹中間一串標記。
現在裁圖在匯入時做（趁 PyMuPDF 還開著那一頁），圖由伺服器代理位元組
而不是發簽名網址，每一個顯示題目的畫面都接上了，含紙本考卷。

**智慧老師。** 引導式教學，Step by Step／Small tips／Basic Topics
三種模式預設自動但學生按得動。**重點不是有一個聊天框，是它不會把
答案講出來**——三層設限，其中後處理閘門吃過 40 種洩漏樣式的測試。
只有學生看得到這一題的檢討時才開得了對話，否則 ON_DUE 的考試在截止
前就能用 AI 把答案問出來。老師看得到班上的對話與哪幾題最多人問。

**能力分析。** 掌握度不是答對率——答對率把三個月前的一題與昨天的
一題算成一樣重。時間加權，半衰期約 97 天（一個暑假）。學生看到的是
可行動的下一步（含前置知識點），老師看到的是全班哪一個章節要重講、
以及依題型的表現。**知識點圖譜是空的時候每一頁都會說出為什麼。**

**考試行為偵測。** 切換分頁、離開全螢幕、貼上（只記字元數不記內容）。
**只記錄不判斷**：瀏覽器層的偵測一定有偽陽性（來電、通知、切輸入法），
自動判定作弊並中斷考試的代價是一個沒作弊的學生被踢出去。老師看到的
是事實加全班比較，沒有風險分數、沒有「可疑」標籤。考試開始前會明確
告知學生。全班都有大量事件時不標記任何人。

**家長端。** 真正的缺口不是畫面而是連結——`linkGuardian` 從來沒有
呼叫端，那張表永遠是空的。現在名冊帶家長信箱就一併建帳號。家長看得到
任務完成狀況與已放行的成績；**看不到逐題作答、檢討、智慧老師的對話、
考試行為事件**，而且是在程式裡真的擋住，直接打 API 也拿不到。

**升學輔導（第一階段）。** 制度規則引擎（管道排他，完整笛卡兒積測試）
與繁星校內賽局模擬。後者是整個模組最有價值的一塊，因為校內競爭的
資料只有學校自己有。學生只看得到自己的序位，人數少於 3 人時連序位
都不給。

**升學資料的查詢動線（v0.24.0）。** 系統自己抓不到全國校系資料
（招聯會 robots.txt 禁止爬取），但**禁止的是機器不是人**。所以改成
三件它真的做得到的事：告訴學生去哪裡查（依繁星時序排的七步清單，
含查證過的官方網址）→ 把查到的記下來（來源類型與查詢日期是必填）
→ AI 老師在上面給建議。

那一層 AI 的風險與智慧老師不同：不是洩漏答案，是**製造假的精確度**。
所以有另一組閘門擋機率預測、「穩上」「有把握」這類措辭、以及任何
對不回資料來源的數字。建議會說出資料基礎有多薄（每年只有一個極值
資料點），而不是給一個百分比。

**學生自己輸入的在校百分比不進入校內賽局模擬**——模擬會影響其他
學生看到的位置，打錯一個數字別人就跟著錯而不自知。模擬只吃教務處
匯入的那一份。

## v0.25.0 補上的最後三塊

**非選題的 AI 閱卷。** 評分規準的三張表從第一版就在 schema 裡而從來
沒有人寫過。現在老師建規準（內建三個範本），AI 給**建議**——而
`AttemptAnswer.earnedScore` 只有兩個寫入者：客觀題的自動計分，與
老師手動輸入。**AI 沒有任何路徑寫得到分數**，四層保證各有測試。
輸入框預設不填入 AI 的分數，因為預填的話老師會直接按確認，那就是
「AI 決定」而不是「AI 提出」。另有一頁看採用率與平均誤差——那是
判斷這個功能該不該繼續開的依據。

**通知。** 只做站內（機房封閉網段寄不出信）。EMAIL／LINE／SMS 三個
渠道**建立後立刻標成 SUPPRESSED 並寫明原因**，不留在佇列裡——
留著等於在說「排隊中」而它永遠不會送，老師會以為家長收到了。
「別人動了你的成績」（作廢、撤銷、代為結算）不可關閉，
「提醒你自己去做某件事」可關。收件匣不做成第二個待辦清單：
待辦由狀態算出來（處理完自己消失），通知由事件算出來。

**級分預測與個申落點。** 原本記成「資料無法合法取得」，兩個理由現在
都不成立：級分不必從作答反推，補習班的模擬考本來就公布級分；
落點的歷年門檻由學生自己查來輸入（v0.24.0 的動線）。
預測一律是區間加信心，而且**會追蹤自己的準確度**——學測成績公布後
回填，算「被預測為 70% 信心的區間，實際命中率是不是接近 70%」。
落點的機率走確定性通道（固定種子、輸入快照、可重算），AI 的文字裡
永遠不出現機率。第二階段不做任何預測。

## v0.27.0：學習歷程輔助與面試準備

**這一塊的界線是「協助整理與回饋可以，代寫不行」**，三層設限，
其中確定性閘門吃過 31 種代寫寫法的測試。

**而規則必須放過自己**：教育部函文要求學生揭露 AI 使用，而揭露聲明
本身就是一段五十幾字的第一人稱敘述——正是防代寫閘門擋的東西。
不排除的話，揭露聲明產生器會被自己的後處理層無限重試。排除的方式是
功能別白名單，而它走另一組規則：**比對聲明內容與實際記錄是否相符**。
宣稱「未使用 AI 生成內容」但記錄裡有十次撰寫回饋的聲明會被擋下來。

**隱私與智慧老師的立場相反**：老師預設看不到、家長任何路徑都讀不到、
**AI 對話連老師都看不到**。差別在內容的性質——智慧老師的對話是
「他在數學第 7 題卡住」，這裡的對話會談到家庭與生涯。

老師可以為班級設定 AI 使用層級（教育部函文要求事前明定），超出層級
的功能對該班學生**停用**。多班取最嚴的一級。

制度上限做成**資料不是常數**，每年對簡章更新，而且填的人要說得出
是從哪一份簡章的哪一頁抄來的。最多人搞錯的那一條有處理：綜整心得
有 800 字加 3 張圖的限制，**但不計入 10 件多元表現的額度**。

送出前有一份確認清單，逐項核對甄選會第二階段那個不可逆的窄口：
每一校系只能擇一使用「勾選中央資料庫」或「自行上傳 PDF」且不得混搭、
系統每日 09:00 至 21:00、**送出確認後不得修改**。

面試回饋**只評結構不評內容**，而且不走模型——模型被要求只評結構時
第三輪就會寫出內容評價並混在結構觀察裡送出去。

## 已知的限制（不是 bug，是還沒做）

**AI 閱卷的規準要老師自己建。** 內建範本的結構照公開制度，但描述
文字是系統自己寫的白話版——出版社與大考中心的評分原則受著作權保護，
不會內建在系統裡。

**建置機器需要能連 Docker Hub 與 binaries.prisma.sh。** Prisma 的查詢
引擎是執行期的硬相依，建置時會下載並烤進映像。企業防火牆很常放行
前者卻擋掉後者，而那會讓建置在第 8 分鐘才失敗；`preflight.sh` 現在
會分開測這兩個目標。機房完全封閉時走離線包：
`./deploy/scripts/build-offline-bundle.sh` 在有網路的同架構機器上打包，
搬過去之後 `sudo ./deploy/scripts/ubuntu-install.sh --offline`。

## 出事的時候

```bash
docker compose ps                       # 誰沒起來
docker compose logs -f web --tail=100   # 應用日誌
curl localhost:3000/api/readyz          # 依賴檢查（第一次可能 503，等 40 秒）
curl localhost:3000/api/version         # 現在跑的是哪一版

./deploy/scripts/doctor.sh              # 一次跑完所有健檢
./deploy/scripts/rollback.sh            # 回到上一版（含資料庫）
```

**回滾之前先看 `/api/version`**，確認你要回的版本號。升級腳本用
`VERSION` 檔當映像標籤，版本對不上的話會回到錯的地方。

考試當天現場要做的事，集中在**任務內頁**（`/assignments/<任務>`，
從「派卷」或「成績」都點得到）：

- **全班網路斷了要補時間**：一次延長所有進行中的作答 N 分鐘，也可以
  只延長某一位（遲到、特殊需求）。延長的是各自的到期時刻，不是把
  大家拉到同一個時間點。也可以立刻結束整場。
- **有人說沒收到考卷**：那一頁列出應交／已開始／已交卷／未動作，
  「未動作」的直接列出姓名——那是你當下要打電話的名單。
- **有人斷線沒交卷**：時間到之後那一份會卡在「進行中」，在成績列表
  的「卡住」欄與首頁待辦都看得到，點進來可以代為結算。
- **抓到作弊或機器壞掉**：在成績頁的學生列表上「作廢」那一份（要填
  理由、進稽核）。作廢不佔作答次數，可以讓他重考。誤判可以撤銷。
- **發現有一題答案錯了**：到題庫改標準答案，或直接在成績頁那一題按
  「全班送分」。兩者都會提示你哪幾份任務要重新計分。

## 部署當天建議做但今天可以先跳過的

- **備份還原演練。** 裝完當天請至少跑一次
  `./deploy/scripts/backup.sh` 再 `./deploy/scripts/verify-restore.sh`
  （順序不能顛倒，自動備份要等到凌晨 03:15）。
  但**「毀掉一台機器再從零還原」從來沒有真的跑過**——
  RTO 4 小時在那之前只是一句話。RPO 的部分見 `docs/DISASTER-RECOVERY.md`
  開頭那張表：機器還在時是 15 分鐘，整台機器毀掉時是最多 24 小時。
- **監控。** `--profile monitoring` 起的是 Grafana ＋ Loki（事後翻日誌），
  **不是會通知你的東西**：告警規則全部處於停用狀態，因為它們引用的指標
  沒有任何元件產生，而且 compose 裡沒有 Alertmanager。
  詳情與現在該靠什麼（`doctor.sh` ＋ 一行 cron）寫在
  `docs/OPERATIONS.md` 的「監控」一節。
- **外部資安檢測。** 重點在水平越權、檔案上傳、提示詞注入三類。

## 這一版驗過的東西

**這張表寫的是「怎麼自己驗一次」，不是一組凍結的數字。**
以前它列的是某一次執行的項數（「311 全過」之類），而那些數字有兩個問題：
一、每改一版就過期，而沒有人記得回來改；
二、**它看不出那些項目是誰跑的**——那 311 項當時沒有被任何 runner 或
CI 引用，是有人記得手動一支一支跑出來的。

| 範圍 | 自己跑一次 | 需要什麼 |
|---|---|---|
| 端到端（匯入、考卷作答、名冊、能力、智慧老師、家長、升學、閱卷、通知、監考、預測、學習歷程，共 13 支） | `npm run test:e2e` | Postgres、Redis、Python（moto ＋ AI 服務）。**一支失敗就整體失敗並印出是哪一支。** |
| 單元測試（計分、AI 閘門、掌握度、考試行為、預測、落點…） | `npm test` | 只要 node |
| Python（AI 管線，17 個測試檔） | `npm run test:ai` | Python 相依 |
| 部署設定（36 項） | `npm run check:deploy` | docker compose 指令（不必真的啟動） |
| 租戶隔離（靜態 6 項；接上資料庫另有 5 項，共 11） | `node tools/rls-check.mjs --static`／不加參數則連資料庫 | 後者要資料庫 |
| TypeScript | `npm run typecheck` | 只要 node |
| schema 漂移 | `node tools/schema-drift.mjs` | 只要 node |
| 全部靜態檢查一次 | `npm run check` | 以上不需服務的都跑一遍 |

`npm run test:e2e`、`npm test`、部署設定、租戶隔離、schema 漂移、TypeScript
現在**都在 CI 裡**（`.github/workflows/ci.yml`）。所以「這一版有沒有過」
看那一次 push 的 CI 結果就好，不必相信文件裡的數字。

考卷與作答那一段做過**突變測試**：故意拿掉一條約束、關掉一張表的
RLS、把外鍵改成 CASCADE——對應的測試立刻轉紅。綠燈但紅不起來的測試
沒有價值。

### `npm run build` 在 repo 根目錄會失敗，那不是壞掉

手動驗證的人常撞到這個：

```
DATABASE_URL Required / REDIS_URL Required / AUTH_SECRET Required
Next.js build worker exited with code: 78
```

原因是 Next.js 讀的是 `apps/web/.env`，**不是根目錄那一份 `.env`**。
`apps/web/lib/env.ts` 在載入時就驗證設定，缺一項就 exit 78。

**Docker 建置不受影響**（`apps/web/Dockerfile` 的 builder 階段帶了明顯是
假的佔位值），所以 `docker-install.sh` 不會遇到這件事。真的要在宿主機
手動 build 的話，先把那幾個必填變數帶進去：

```bash
set -a; . ./.env; set +a
npm run build
```

**沒有驗過的**：Docker 映像實際建置與啟動（這個沙箱連不到 Docker Hub）、
AI 模型的實際準確率（連不到你的端點）、300 人同時作答的負載。
前兩件都要在你的機器上做，而第一件就是 `docker-install.sh` 本身。
