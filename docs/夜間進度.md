## 一、先講 AI 端點：連不上，而且不是設定問題

你給的 `https://你的閘道網域` 我第一件事就去測，**連不上**。

診斷結果很明確：這個沙箱有一層出口代理，只放行 `anthropic.com` 與
套件庫（npm、PyPI）。`api.openai.com` 也是**同一個 403**，所以不是
你的端點被擋，是所有非允許清單的對外連線都被擋。我不會去繞過它。

```
你的閘道網域          → Tunnel connection failed: 403 Forbidden
api.openai.com        → Tunnel connection failed: 403 Forbidden   ← 同樣
registry.npmjs.org    → 200
```

**所以實跑驗證要在你那邊做，而我把它變成兩行指令。** 金鑰我放在
`/home/claude/.yunzhi-ai.env`（chmod 600、在 repo 之外，不可能被
commit），全程沒有出現在任何輸出或檔案裡。

### 你醒來之後跑這個

```bash
export AI_PROVIDER=openai
export AI_BASE_URL=https://你的閘道網域/v1      # 注意結尾的 /v1
export AI_API_KEY=<你的金鑰>
export AI_MODEL_HIGH=gpt-5.6-sol
export AI_MODEL_MID=gpt-5.6-sol
export AI_MODEL_LIGHT=gpt-5.6-sol

python3 tools/ai-preflight.py        # 二十秒，幾乎不花錢
python3 tools/verify-ai.py --pages 6 # 過了再跑，會產出一份報告
```

### 我先把最可能讓第一次就失敗的東西修掉了

「OpenAI 相容」不是一個規格，是一個大致的方向。`gpt-5.6-sol` 這種
新一代模型名稱，很可能在第一個請求就被以下三件事之一擋下來，
而且全部是 400、只有真的送出去才知道：

| 症狀 | 原因 |
|---|---|
| `Unsupported parameter: 'max_tokens'` | 新一代推理模型只吃 `max_completion_tokens` |
| `Unsupported value: 'temperature'` | 推理模型只接受預設值，給 0.0 也被拒 |
| `Invalid image_url: unknown field 'detail'` | 有些閘道不認得高解析模式 |

要求你自己去查「我的閘道屬於哪一種」不合理——你手上只有一個網址、
一把金鑰、一個模型名稱。所以我做了**參數協商**：先送最通用的形狀，
被 400 拒絕而且錯誤訊息指名了某個參數時，自動換一種形狀重送，
並把結論記下來，之後不再試錯。七項測試涵蓋這三種情況與「真的錯誤
要照樣拋出來」（把真錯誤吞掉的症狀是無盡重試）。

### 預檢會問四個問題，依「錯了會不會讓整個設計失效」排序

1. **連得到、認證過、模型認得。**
2. **看得懂圖嗎。** 這一項最重要——整條匯入管線是「模型讀整頁影像」
   設計的。模型不吃 images 的話那個設計不成立，要退回規則路徑，
   而規則路徑對掃描件與翻拍照片幾乎沒有用。預檢用的測試圖刻意是
   一道台灣體例的題目（五個半形括號選項＋中文題幹），不是
   `hello world`——「讀得出英數卻認不得中文版面」是這條管線真實會
   遇到的失敗，而一張只有英文的圖看不出來。
3. **吐得出通過驗證的 JSON 嗎。**
4. **回報 token 用量嗎。** 沒有的話預算上限與成本外推都是估的。

### B0.1 租戶隔離下沉到資料庫（v0.15.0）

42 張表全覆蓋的 Postgres row-level security。三個設計重點：

**FORCE。** 少了它，應用程式用資料表擁有者身分連線時 RLS 形同虛設
——而那正是最常見的部署方式。

**Fail closed。** 沒設租戶時 `current_setting` 回 NULL，
而 `NULL = 任何值` 是 NULL 不是 true，所以什麼都查不到。忘記設比
設錯常見得多，而忘記設必須是「查不到東西」而不是「查到全部」。

**`set_config` 的第三個參數是 true（只在交易內有效）。** 設成
session 層級的話，連線還回池子時會帶著上一個請求的租戶——那種洩漏
與程式碼無關、只跟連線池這次剛好給了哪一條連線有關，所以會偶發、
無法重現、測不出來。

新增資料表而沒有決定它屬於誰，`tools/rls-check.mjs` 就會失敗。
一張沒有人注意的表對所有租戶敞開，不會有任何錯誤訊息。

**順手抓到一個真的安全問題**：登出只有 token、不知道租戶，
RLS 底下 `deleteMany` 比對不到任何一列——cookie 清掉了，
但伺服器端的 session 還活著，而畫面上看起來完全正常。
考試場景「發現代考立刻登出那個帳號」的能力就是這樣消失的。

### B0.2 元件基礎（v0.16.0）

設計系統早就在了（globals.css 的「校樣」方向），缺的是 React 元件
——校對介面與上傳表單各自把按鈕、輸入框、對話框重刻了一遍。

七個零件，每一個都針對「不做也看不出來、直到有人真的需要」的事：
label/id/aria 綁定、送出中停用按鈕、4xx 不被當成成功、
用 ref 擋連點兩次（`setState` 是非同步的，兩次點擊可能都讀到
`busy=false`，而派任務與交卷送出兩次是真的會出事的）、
四種空狀態分開（把「出錯」畫成「空的」會讓老師以為題庫是空的，
然後重新匯入一次已經在裡面的題本）。

**校樣頁**（`component-gallery.png`，附在下面）用真的元件靜態渲染，
不是另外手刻一份示意圖——手刻的會分岐，然後你看到的漂亮版本跟
系統裡的不是同一個東西。

它立刻抓到兩個真問題：校樣的表單區被我手刻成裸 HTML（**正是它要防
的分岐**），以及 `thead th` 的 `text-align:left` 特異度比
`.yz-table__num` 高，導致數字欄標題靠左而數值靠右——而數字欄存在
的理由就是為了對得齊。

### B0.3 班級與名冊（v0.17.0）

在此之前 `Class` 只在測試裡被建立過、`ClassMembership` 只被讀過從來
沒被寫過——**沒有任何方式可以建一個班、把學生放進去**。

CSV 讀取是這一批最有價值的一段，因為它針對名冊真正的來源：櫃檯用
Excel 開啟舊名冊，「另存新檔 → CSV」。

| 真實狀況 | 不處理的後果 |
|---|---|
| Windows 版 Excel 在繁中系統存出來是 **Big5** | 整份亂碼 |
| 「CSV UTF-8」帶 BOM | 第一欄變 `﻿學號`，「找不到學號欄」，而檔案看起來完全正常 |
| 民國年「95/3/2」 | 被當成西元 95 年，差 1911 年——而它直接決定「是不是未成年」，那決定要不要取得法定代理人同意 |
| 「95/2/30」 | JS 的 `Date` 會靜靜地變成 3 月 2 日不報錯，名冊上的錯字變成一個看起來正常的生日 |
| 欄位標題五花八門 | 要求先整理一次資料，等於要求他們先做那件想用系統來避免的事 |

判定順序不能反：UTF-8 的中文用 Big5 解得開（會得到亂碼但不報錯），
所以先試嚴格 UTF-8，解不開才退 Big5。

**兩個貫穿的決定：**

*名冊匯入是全有全無。* 32 人的名冊第 7 列撞號時整份都不匯入。
部分匯入之後沒有人知道現在是什麼狀態——櫃檯改好第 7 列再匯一次，
前 6 位就變成重複。這件事發生在開學前一天，錯了的代價是有學生
登不進去。所以介面是兩段式：先試算（看得到「新增 28 位、4 位已有
帳號、第 7 列有問題」）再確認，寫入包在一個交易裡。

*學生帳號預設不能登入，直到家長同意。* 個資法第 15 條要求蒐集
未成年人的個人資料需法定代理人同意。沒有同意紀錄，整個資料庫的
合法性都有疑問，所以預設擋住而不是預設放行再補簽。同意的取得方式
（現場／線上／紙本）記進稽核——現場簽與線上簽的證據力不同。

初始密碼刻意避開 `0/O` 與 `1/l/I`：這串字會被印在紙上發給學生，
「登不進去」的客服成本遠高於少幾個字元的熵。

### B0.4 知識點圖譜（v0.18.0）

文件 05 說它是「唯一一個不能延後的前置項」。實際狀況是
`KnowledgePoint` 只被讀、從來沒被寫，全庫只有 10 筆種子資料——
所以**匯入管線的標註階段實際上是失效的**，它只會回報「找不到合適
的候選知識點」。

重點在環路偵測。環不是有人故意加的，是三位老師各自加了一條邊之後
湊出來的：

```
甲：三角函數   需要 弧度
乙：弧度       需要 圓的方程式
丙：圓的方程式 需要 三角函數      ← 這一條把環閉合了
```

丙老師看不到前兩條的組合效果。所以偵測必須在**加邊的當下**做，
而且訊息要指出整條環路——只說「不能加」的話他只會覺得系統壞了。

有環的代價很具體：智慧老師往回找前置觀念、能力分析往下傳學分，
兩者都是遞迴，**都會無限迴圈**。

圖論部分抽成沒有相依的 `graph.mjs`，所以測得動：自環、直接互指、
三方湊出來的環、長鏈不誤判、鑽石形不是環、拓樸排序、以及掃出既有
資料裡的環（偵測是後來才加的，之前建的資料可能已經有環）。
